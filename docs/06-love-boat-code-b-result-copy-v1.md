# 星星戀愛日記｜暈船法典 V1
## B 層結果文案庫：他實際怎麼回應我？

版本：V1 Draft
用途：Milestone 4B－暈船法典
定位：觀察互動工具，不替使用者猜測對方內心、不判斷對方好壞、不做關係診斷。

---

## 1. B 層目的

B 層只回答一件事：

> **從目前真正發生過的互動來看，對方實際有多少回應？**

B 層不回答：
- 他到底喜不喜歡我
- 他是不是「對的人」
- 他是不是渣男／渣女
- 我們一定會不會在一起
- 這段關係值不值得繼續
- 他心裡真正怎麼想

核心原則：

> **先不猜他的心，只看目前真正發生過的行動。**

---

## 2. 題目與選項

共 10 題。

每題選項：

- `2` 有
- `1` 有時
- `0` 沒有
- `X` 還不知道

`X` 不視為負分，也不納入該次比例計算。

### B01
他也會主動聯絡我，而不是總是等我先找他。

### B02
他願意安排時間和我相處。

### B03
他答應我的事情，大多會做到。

### B04
當我表達感受或想法時，他願意聽我說。

### B05
他會記得一些我曾經告訴他、對我來說重要的事情。

### B06
當我們之間需要溝通時，他通常不會無故消失。

### B07
他的行動和他說過的話，大致是一致的。

### B08
這段互動不是一直只有我一個人在主動維持。

### B09
在我們目前的關係裡，我大致知道自己處在什麼位置。

### B10
和他互動時，我通常不需要一直猜測他的意思。

---

## 3. 計分原則

### 3.1 不直接用固定 20 分判斷

因為「還不知道」不應該被當成 0 分。

例如：

- 使用者只認識對方兩週
- 有 4 題還無法判斷
- 這些未知不代表對方沒有回應

因此 B 層應使用「已回答題目的回應比例」。

### 3.2 計算方式

```ts
answeredItems = count(answer !== "unknown")
earnedScore = sum(有=2, 有時=1, 沒有=0)
maxPossibleScore = answeredItems * 2

responseRatio =
  maxPossibleScore > 0
    ? earnedScore / maxPossibleScore
    : null
```

顯示比例可轉為百分比供內部計算，但 **V1 結果頁不必顯示百分比**。

---

## 4. 最低觀察門檻

若 10 題中，使用者能明確回答的題目少於 4 題：

```text
answeredItems < 4
```

不要強制分級。

使用：

`response_insufficient_observation`

顯示名稱：

> **還需要一點時間觀察**

原因：

認識時間太短或互動太少時，App 不應該因資訊不足而替關係下結論。

---

# 5. B 層分級

當 `answeredItems >= 4` 時：

| stable key | 回應比例 | 顯示名稱 |
|---|---:|---|
| `response_low` | 0%–34% | 目前看到的回應比較少 |
| `response_mixed` | 35%–59% | 有一些回應，也有一些不確定 |
| `response_good` | 60%–79% | 你已經看見不少實際回應 |
| `response_high` | 80%–100% | 目前的互動大致有來有往 |

> 這些只是「目前觀察到的互動狀態」，不是關係品質分數，也不是對方人格判定。

# 6. 結果文案池

## 特殊狀態｜`response_insufficient_observation`
### 還需要一點時間觀察

### `response_insufficient_observation_01`
現在可能還沒有足夠的互動，讓你看清這段關係。與其急著猜他的心，不如再給彼此一點時間，看看之後的行動會怎麼發展。

### `response_insufficient_observation_02`
有些事情現在是真的還不知道。這不是壞事，也不代表沒有希望，只是目前的資訊還不夠。讓時間和之後的互動慢慢補上答案。

### `response_insufficient_observation_03`
你現在能觀察到的事情還不多，所以先不用急著替這段關係下結論。比起猜測，接下來真正發生的行動會更有參考價值。

---

## Level 1｜`response_low`
### 目前看到的回應比較少

### `response_low_01`
從你目前觀察到的互動來看，對方實際表現出的回應還比較少。這不代表我們知道他的心，只代表現在真正能看見的行動並不多。

### `response_low_02`
目前這段互動裡，你能明確感受到的回應比較有限。先不用急著替他找理由，也不用急著下結論，接下來可以繼續看看他的行動是否會慢慢出現。

### `response_low_03`
你現在看到的訊號似乎還不算多。與其一直猜「他到底怎麼想」，也許更值得觀察的是：之後他會不會主動、投入時間，或用行動回應這段關係。

### `response_low_04`
目前能確認的回應比較少，所以有些事情可能還停留在你的期待或猜測裡。關係不用急著定義，讓真正發生的互動再多說一點話。

### `response_low_05`
現在看起來，這段互動的回應還不是很明顯。你不用因此否定自己的喜歡，只是可以先慢一點，讓對方的行動也有機會跟上。

---

## Level 2｜`response_mixed`
### 有一些回應，也有一些不確定

### `response_mixed_01`
你已經看見一些實際回應，但也有幾個地方還不是很確定。這可能代表關係正在發展，也可能只是彼此還需要更多時間了解。

### `response_mixed_02`
這段互動不是完全沒有回應，只是目前還不算穩定。有些時候你能感受到對方靠近，有些時候又會讓你猜測。可以先繼續觀察一致性。

### `response_mixed_03`
你目前收到的訊號有好有壞，也還有一些模糊的地方。與其只記住特別甜或特別冷的那一次，更值得看看一段時間裡，他的行動是不是大致一致。

### `response_mixed_04`
對方並不是完全沒有回應，但目前似乎還有一些地方需要時間確認。你不用急著把一兩次互動放大成答案，可以多看看整體。

### `response_mixed_05`
你已經感受到一些互動是有來有往的，同時也還有幾個問號。現在最有用的不是猜得更用力，而是讓後續的行動慢慢把那些問號變清楚。

---

## Level 3｜`response_good`
### 你已經看見不少實際回應

### `response_good_01`
從目前的互動來看，你已經觀察到不少實際回應。對方並不是只有說說而已，在一些重要的地方也有用行動參與這段關係。

### `response_good_02`
目前你看到的互動裡，有不少地方是有回應的。你不需要只靠想像來支撐這段關係，因為已經有一些真實發生的行動可以觀察。

### `response_good_03`
對方目前在不少互動上都有實際回應。當然，這仍然不能替他的內心下結論，但至少這段關係不是完全只存在於你的期待裡。

### `response_good_04`
你目前觀察到的行動，大多能讓你感受到對方有在參與這段互動。接下來不用急著追求更多答案，可以繼續看看這些回應是否穩定。

### `response_good_05`
這段關係裡已經出現不少有來有往的互動。比起一直猜他的心，你其實已經有一些真實的行動可以作為觀察的依據。

---

## Level 4｜`response_high`
### 目前的互動大致有來有往

### `response_high_01`
從你目前能觀察到的事情來看，這段互動大致是有來有往的。對方在主動、時間、傾聽或行動一致性等面向，多半有實際參與。

### `response_high_02`
目前這段關係不只是你的單方面投入。你已經看見不少具體的回應，也比較不需要完全靠猜測來理解彼此的互動。

### `response_high_03`
從現在的行動來看，對方大多有回應這段關係。這並不能預言未來，但至少此刻你看到的，不只是自己的期待。

### `response_high_04`
目前你們的互動裡，有不少雙向的痕跡。對方的言語與行動多半能讓你感受到回應。接下來仍然可以慢慢走，不需要急著替關係下最後答案。

### `response_high_05`
你目前觀察到的互動大致穩定，也有不少實際回應。比起一直問「他到底喜不喜歡我」，現在已經有一些行動值得你慢慢看下去。

# 7. 單題不作負面判決

B 層不得因單一題目為 `0` 就直接生成負面結論。

例如：

- B01「不主動聯絡」= 0
- 但 B02～B10 多數為 2

App 不可以生成：

> 他不主動，所以他可能不夠喜歡你。

應改為整體判斷：

> 主動聯絡是目前比較少出現的互動，但其他面向仍需要一起看。

原因：

人的互動風格不同，單一行為不足以推論對方的感情、人格或關係意圖。

---

# 8. 可選的「值得再觀察」提示

除了主要結果文案，App 可以從答案中找出最多 1～2 個分數較低的觀察面向，產生純規則式提示。

例如：

### B01 = 0
> **可以再觀察：主動性**
> 目前主動聯絡比較常由你開始，之後可以看看這個模式是否一直如此。

### B03 = 0
> **可以再觀察：說到做到**
> 與其只看承諾，可以多看看之後的行動是否一致。

### B04 = 0
> **可以再觀察：傾聽**
> 當你表達感受時，可以看看對方是否願意理解，而不只是快速結束話題。

### B06 = 0
> **可以再觀察：溝通時的存在感**
> 發生需要溝通的事情時，可以留意對方是願意面對，還是經常避開。

### B07 = 0
> **可以再觀察：言行一致**
> 不急著判斷對錯，先看看一段時間裡，他說的和做的是否大致相符。

### B08 = 0
> **可以再觀察：互動是不是雙向**
> 可以留意這段關係是不是長期都需要由你一個人推進。

### B09 = 0
> **可以再觀察：關係中的清楚感**
> 如果長期不知道自己處在什麼位置，這本身就是值得繼續觀察的感受。

### B10 = 0
> **可以再觀察：你是否一直需要猜**
> 一段互動如果長期需要大量猜測，可以留意之後是否逐漸變得更清楚。

規則：
- 最多顯示 2 個
- 優先挑 `0` 分題目
- 若沒有 `0`，可選 1 個 `1` 分題目
- 不使用「警訊」「紅旗」「危險人物」等標籤
- 不生成分手／繼續交往建議

# 9. 文案輪替規則

V1 不使用 AI。

每個 B 層結果維護多組預寫文案：

- `response_low`：5 組
- `response_mixed`：5 組
- `response_good`：5 組
- `response_high`：5 組
- `response_insufficient_observation`：3 組

輪替原則：

1. 優先顯示尚未看過的版本。
2. 全部看過後重新循環。
3. 不純 random，避免連續看到相同文案。
4. 切換到新分級時，使用該分級自己的輪替狀態。
5. 文案版本只影響顯示，不影響分數與資料。
6. 所有文案需透過 i18n key 取得。

示意：

```ts
type ResponseLevel =
  | "response_insufficient_observation"
  | "response_low"
  | "response_mixed"
  | "response_good"
  | "response_high"

type ResultCopyState = {
  resultKey: ResponseLevel
  lastVariantIndex: number
}
```

# 10. 與上一次測驗比較

只有當前後兩次都有至少 4 題有效觀察時，才比較 B 層變化。

建議用 `responseRatio` 差值。

### 明顯增加
若：

```text
currentRatio - previousRatio >= 0.15
```

可顯示：

> 和上一次相比，你這次觀察到的實際回應變多了一些。

### 大致持平
若：

```text
-0.14 <= difference <= +0.14
```

可顯示：

> 和上一次相比，你目前觀察到的互動狀態沒有太大變化。

### 明顯減少
若：

```text
currentRatio - previousRatio <= -0.15
```

可顯示：

> 和上一次相比，你這次觀察到的實際回應少了一些。先不用急著下結論，可以再看看這是不是短期變化。

注意：
- 「增加」不等於關係變好
- 「減少」不等於關係變壞
- 只描述使用者此次記錄到的互動變化

# 11. 語氣規範

所有 B 層文案必須：

- 描述「目前觀察」
- 使用「目前」「現在」「從你觀察到的互動來看」等時間限定
- 不推論對方內心
- 不判斷人格
- 不做愛情預測
- 不使用「渣男／渣女」
- 不使用「紅旗人物」
- 不使用「他就是不愛你」
- 不使用「他一定喜歡你」
- 不指示使用者分手或繼續
- 不把未知答案當成負面答案
- 不因一個低分項目判斷整段關係

核心語氣：

> **不急著猜他怎麼想，先看看他實際怎麼做。**

# 12. V1 實作原則

- Local First
- 不使用 OpenAI API
- 不使用其他 AI API
- 不生成 AI 評語
- 使用固定計分規則
- 使用預寫多版本文字池
- stable key 儲存於資料層
- 所有 UI 文字走 i18n
- `unknown` 不等於 `0`
- 至少 4 題有效回答才分級
- 測驗可以重做
- 每次測驗保留：
  - raw answers
  - answered item count
  - earned score
  - response ratio
  - response level
  - localDate
  - timezone
  - createdAt
- B 層本身不增加星心值
- 是否存成清醒星星，待完整 A+B 規則一起決定

# 13. 建議資料欄位

```ts
type BoatResponseAnswer = 0 | 1 | 2 | "unknown"

type BoatResponseAssessment = {
  answers: Record<BoatResponseQuestionKey, BoatResponseAnswer>
  answeredItems: number
  earnedScore: number
  maxPossibleScore: number
  responseRatio?: number
  responseLevel: ResponseLevel
}
```

不要只保存最後分級，應保留每題答案，方便：

- 重開紀錄
- 查看歷史
- 比較前後變化
- 未來調整演算法時重新計算
- 顯示「值得再觀察」項目

---

# 14. 與 A 層的關係

A 層：

> **我投入多少？**

B 層：

> **目前我實際收到多少回應？**

兩者不能單獨替關係下結論。

最終結果需由 A+B 交叉：

```text
我的投入 × 對方目前的回應
```

例如：

- 高投入 × 高回應
- 高投入 × 低回應
- 低投入 × 高回應
- 低投入 × 低回應

但正式 V1 建議保留更多中間狀態，而不是硬切四象限。
