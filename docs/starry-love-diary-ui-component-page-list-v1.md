# 《星星戀愛日記 UI 元件與頁面清單 v1》

版本：v1.0  
用途：作為《星星戀愛日記》V1 的 UI/UX 設計、頁面資訊架構與 Codex 開發基準。  
建議放置：`docs/ui-component-page-list-v1.md`

---

# 1. UI 設計目標

《星星戀愛日記》的 UI 必須同時做到：

- 可愛、療癒，但不過度女性化
- 具有戀愛感，但不幼稚
- 有花園、星光、夜空、柔和粉彩元素
- 能同時吸引女性與男性使用者
- 內容多時仍然保持乾淨、好讀
- 主畫面可以有角色插畫，但功能頁以清楚、好操作為優先
- 不做商城感、寵物養成感、任務壓力感
- 不把功能做得像心理治療 App
- 所有文字由程式顯示，不燒進圖片
- 從第一天就支援多語系與長文字適配

---

# 2. V1 底部固定導覽

底部固定 5 個主頁：

1. **今天**
2. **星星瓶**
3. **足跡**
4. **我們**
5. **清醒**

另外：

- **設定／工具** 不放在底部導覽
- 五個主頁右上角都提供固定 `⚙️` 入口
- 設定頁為次級頁面，可垂直捲動

# 3. 全域視覺系統

## 3.1 主色方向

建議以柔和粉彩為主：

- 粉紅：主要戀愛／心動色
- 奶油白：主背景與卡片底色
- 淡藍：對方／中性平衡
- 淡黃：星光、提醒與溫暖
- 淡紫：想念、清醒與夜空感
- 淡綠：安心、回到自己

原則：

- 不使用高飽和霓虹色
- 避免大面積深黑背景
- 所有文字需符合可讀性與對比需求

---

## 3.2 圓角與卡片

建議統一：

- 大卡片：20～28px 圓角
- 小卡片：14～20px 圓角
- 膠囊按鈕：全圓角
- 卡片陰影柔和，不做厚重立體陰影
- 重要卡片可加淡淡星光、蝴蝶結、花朵等品牌裝飾

---

## 3.3 字體階層

建議程式內至少定義：

- `Display`：首頁主標／大數字
- `H1`：頁面標題
- `H2`：區塊標題
- `Body`：一般內容
- `Caption`：日期、補充資訊
- `Button`：按鈕文字
- `Quote`：戀愛星語與心話

所有尺寸使用 token 管理，不在頁面中散落硬編碼。

---

## 3.4 Icon 風格

- 圓潤
- 可愛
- 線條不過細
- 與現有「今天心情」icon 語言一致
- 底部導覽 icon 要一眼可辨識

建議：

- 今天：日記／愛心
- 星星瓶：星星瓶
- 足跡：腳印
- 我們：雙愛心／對話
- 清醒：月亮／清醒符號
- 設定：齒輪

# 10. 「清醒」頁

核心問題：

> **當我開始失去自己，我怎麼重新看清楚？**

這是《星星戀愛日記》的主要差異化頁面。

## 10.1 清醒首頁內容順序

1. AppHeader
2. 「今天，我需要哪一種清醒？」導引入口
3. 開始整理心情
4. 暈船法典
5. 戀愛腦檢測
6. 喜歡？習慣？
7. 最近一次整理
8. 最近清醒紀錄
9. 清醒星語
10. BottomNavigation

---

## 10.2 導引入口

標題：

**今天，我需要哪一種清醒？**

選項例：

- 我一直想他
- 我在等他的訊息
- 我覺得自己暈太深
- 我不知道還喜不喜歡他
- 我不知道這個人適不適合我

點擊後直接導向適合功能：

- 一直想他 → 開始整理心情
- 等訊息 → 開始整理心情
- 暈太深 → 暈船法典
- 不知道還喜不喜歡 → 喜歡？習慣？
- 不知道對方適不適合 → 暈船法典「暈錯人」

---

## 10.3 開始整理心情

流程：

1. 選擇困擾情境
2. 事實
3. 我的解讀
4. 還不知道
5. 情緒與強度
6. 必要時進入關係訊號
7. 我現在可以為自己做什麼
8. 生成清醒小結

完成後可：

- 保存清醒紀錄
- 存成清醒星星
- 寫進日記

---

## 10.4 暈船法典

兩大章：

### A. 我是不是暈太深？

觀察：

- 等訊息
- 重播對話
- 狂看社群
- 過度解讀
- 情緒被對方牽動
- 犧牲自己的生活
- 太快投入

### B. 我是不是暈錯人？

觀察：

- 忽冷忽熱
- 消失又出現
- 說很多、做很少
- 模糊承諾
- 只在需要時出現
- 長期讓人猜測
- 不尊重界線

原則：

- 不直接判定「海王／海后」
- 只提示「值得注意的高風險互動訊號」
- 顯示分層結果與建議

---

## 10.5 戀愛腦檢測

可能類型：

- 反芻型
- 訊息依賴型
- 過度解讀型
- 偵探型
- 自我犧牲型

規則：

- 約 25～30 題
- 本機規則計分
- 無 AI API
- 可隨時重測
- 不設 30 天限制
- 可保留歷次結果與日期

---

## 10.6 喜歡？習慣？

主標：

**喜歡？習慣？**

副標：

> 到底是我真的喜歡他，還是我只是習慣有他？

內部觀察維度：

- 真實喜歡
- 習慣／依戀
- 回憶留戀

結果語氣避免心理學術語。

# 14. V1 UI 開發原則

1. 不要邊寫功能邊臨時決定視覺。
2. 所有頁面優先共用元件。
3. 不把文字寫死在圖片裡。
4. 所有列表都要有空狀態。
5. 所有刪除動作都要有安全確認。
6. 所有分享都由使用者主動觸發。
7. 頁面內容多時使用垂直捲動，不硬塞在單屏。
8. 底部導覽固定，不隨內容長度跑掉。
9. 支援 Dynamic Type／長文字與多語系。
10. 西班牙文與法文作為長字串壓力測試。
11. 日期與「今天」一律使用手機本地日期與時區。
12. UI 可愛，但功能操作必須先於裝飾。

# 17. 最終原則

《星星戀愛日記》的 UI 不只是可愛。

它應該讓使用者很自然地完成三件事：

> **記錄自己。**  
> **慢慢了解對方。**  
> **在愛裡仍然看得見自己。**

這三件事就是 V1 所有 UI 設計與功能取捨的最高原則。
