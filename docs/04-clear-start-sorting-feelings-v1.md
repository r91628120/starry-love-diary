# 04｜開始整理心情 V1 規格

## 1. 功能定位

「開始整理心情」不是測驗，也不是 AI 判斷工具。

它的目的，是在使用者因為某個人、某件事開始內耗時，陪使用者把「發生的事、自己的想法、情緒、觀察、需要與下一步」慢慢分開。

V1 原則：

- 不使用 AI
- 不呼叫外部 API
- 不分析對方人格
- 不判斷誰對誰錯
- 不診斷使用者
- 不判斷關係好壞
- 不產生愛情百分比
- 不自動替使用者分類文字
- 所有內容由使用者自己選擇、輸入與確認
- Local First，可在本機完成

核心精神：

> 《星星戀愛日記》不是替你想，而是陪你把自己的想法看清楚。

---

## 2. 六步流程總覽

| Step | 畫面 | 核心問題 | 主要資料 | 必填 |
|---|---|---|---|---|
| 1 | 發生什麼事？ | 是什麼事情讓我開始一直想？ | 情境類型＋事件文字 | 情境或文字至少一項 |
| 2 | 先把事情分開看看 | 哪些是事實？哪些是我的解讀？ | 事實／解讀／還不知道 | 事實或解讀至少一項 |
| 3 | 現在的我，是什麼感覺？ | 我正在感受什麼？ | 情緒＋強度＋身體感受 | 至少一個情緒 |
| 4 | 先不猜他的心 | 不猜他的心，我實際觀察到了什麼？ | 行為觀察 | 選填，可跳過 |
| 5 | 現在，我真正需要的是什麼？ | 我現在需要什麼？我願意為自己做什麼？ | 需要＋下一步行動 | 至少一個下一步 |
| 6 | 這次，我看見了什麼？ | 把這次整理重新看一次 | 自動摘要 | 無額外輸入 |

---

# Step 1｜發生什麼事？

## 畫面主標題

**發生什麼事？**

輔助文字：

> 剛剛發生了什麼，讓你開始一直想？

## A. 情境快捷選項

V1 使用 stable key：

| Key | 顯示文字 |
|---|---|
| `no_reply` | 他沒有回訊息 |
| `attitude_changed` | 他的態度好像變了 |
| `social_media` | 我看到他的社群／動態 |
| `argument` | 我們發生了不愉快 |
| `missing_them` | 我突然很想他 |
| `waiting_response` | 我在等他的回應 |
| `overthinking` | 我開始胡思亂想 |
| `other` | 其他 |

規則：

- 單選
- 此分類只作為紀錄，不代表 App 對事件做分析或診斷

## B. 自由文字

欄位文字：

**如果你願意，可以簡單寫下剛剛發生的事。**

規則：

- 上限 300 字
- 顯示即時計數，例如 `38 / 300`
- 禁止靜默截斷
- 超過 300 字時不得完成／儲存，需提示使用者修改

## 完成條件

以下任一成立即可：

- 已選擇一個情境
- 已填寫事件文字

不強迫兩者都完成。

---

# Step 2｜先把事情分開看看

## 畫面主標題

**先把事情分開看看**

輔助文字：

> 有些事情是我們確定知道的，有些是腦中正在猜的，也有一些現在還沒有答案。

## 三個文字區塊

### 我確定知道的

說明：

> 可以直接觀察、確認的事情。

- 上限 300 字
- Placeholder 範例：`例如：我昨晚傳訊息，他現在還沒有回。`

### 我腦中正在想的

說明：

> 我的推測、擔心、解讀或想像。

- 上限 300 字
- Placeholder 範例：`例如：他是不是不想理我了？`

### 我現在還不知道的

說明：

> 現在還沒有答案的部分。

- 上限 300 字
- Placeholder 範例：`例如：他現在沒有回覆的原因。`

Placeholder 只作為提示，不得存成使用者資料。

## 完成條件

以下至少一項有內容：

- `facts`
- `interpretation`

`unknown` 可以空白。

## V1 原則

App 不自動判斷：

- 哪一句是事實
- 哪一句是推測
- 哪一句是腦補

分類本身就是使用者的覺察過程。

---

# Step 3｜現在的我，是什麼感覺？

## 畫面主標題

**現在的我，是什麼感覺？**

## A. 情緒

允許複選。

| Key | 顯示文字 |
|---|---|
| `missing` | 想念 |
| `anxious` | 不安 |
| `sad` | 難過 |
| `hurt` | 委屈 |
| `angry` | 生氣 |
| `jealous` | 嫉妒 |
| `afraid` | 害怕 |
| `lost` | 失落 |
| `confused` | 混亂 |
| `hopeful` | 期待 |

至少選擇一項。

## B. 情緒強度

問題：

**這份感覺現在有多強？**

採 1～5：

- 1：很輕
- 2：偏輕
- 3：中等
- 4：偏強
- 5：很強

V1 採整筆情緒共用一個強度，不需要每一種情緒各自評分。

## C. 身體感受

選填，可複選：

- 胸口緊
- 心跳快
- 胃不舒服
- 坐立難安
- 很疲累
- 睡不著
- 想哭
- 沒有明顯感覺
- 其他

V1 不需要長篇文字描述。

## 完成條件

至少選擇一個情緒。

# Step 4｜先不猜他的心

## 畫面主標題

**先不猜他的心**

輔助文字：

> 不急著猜他怎麼想，先看看你真正觀察到的互動。

## V1 觀察項目

每題提供：

- 有
- 沒有
- 不確定

觀察題目：

1. 他會主動聯絡我
2. 他願意花時間和我相處
3. 他說過的事情通常會做到
4. 我表達感受時，他願意聽
5. 我們的互動不總是只有我主動
6. 他的言語和行動大致一致

## V1 原則

此頁：

- 不計分
- 不判斷紅旗
- 不判斷對方是否適合
- 不產生關係結論

即使所有題目都選「沒有」，App 也不能顯示「這個人不適合你」。

可使用中性文字：

> 這是你目前觀察到的互動。

## 完成條件

無。

此頁可跳過。

建議跳過按鈕：

**稍後再想**

---

# Step 5｜現在，我真正需要的是什麼？

## 畫面主標題

**現在，我真正需要的是什麼？**

## A. 我的需要

可複選，選填：

- 安心
- 被理解
- 被尊重
- 有人陪伴
- 一點自己的空間
- 把事情說清楚
- 確認自己的界線
- 暫時休息
- 把注意力拉回生活
- 我還不知道

## B. 我現在願意為自己做什麼？

至少選擇一個下一步行動。

V1 快捷選項：

- 先放下手機一段時間
- 暫時不再查看他的動態
- 去洗澡／休息
- 出去走一走
- 做自己原本要做的事
- 找信任的人聊聊
- 等情緒比較平靜再回訊息
- 明天再決定
- 寫進今天的日記
- 自己寫一個行動

若選擇「自己寫一個行動」：

- 顯示自由文字欄位
- 上限 150 字
- 禁止靜默截斷

## 完成條件

以下任一成立：

- 已選擇至少一個預設下一步行動
- 已填寫一個自訂行動

---

# Step 6｜這次，我看見了什麼？

## 畫面主標題

**這次，我看見了什麼？**

此頁不要求使用者再次輸入文字。

由本機程式將前五步資料組合為摘要。

不是 AI 摘要。

## 摘要範例

> **剛剛發生的事**
> 他今天還沒有回我的訊息。
>
> **我確定知道的**
> 昨天晚上傳出的訊息，到今天下午還沒有回覆。
>
> **我腦中正在想的**
> 他是不是開始不想理我。
>
> **我還不知道的**
> 他沒有回覆的原因。
>
> **現在的我**
> 不安、想念｜4 / 5
>
> **我真正需要的是**
> 安心、暫時休息。
>
> **我現在願意為自己做的事**
> 今晚先不再查看訊息，先去休息。

## 固定收尾文字

> **你現在不需要立刻知道這段關係的答案，只要先照顧此刻的自己。**

## 主要動作

1. **完成這次整理**
2. 完成後可再選擇 **存成清醒星星**

---

# 3. Clear 完成條件

一筆「開始整理心情」要正式完成，必須符合：

## Step 1

有以下任一：

- 情境類型
- 事件文字

## Step 2

有以下任一：

- 事實
- 解讀

## Step 3

- 至少一個情緒

## Step 5

- 至少一個下一步行動

Step 4 不強制。

Step 6 為摘要，不需要額外輸入。

只有使用者在 Step 6 按下：

**完成這次整理**

才正式建立 `ClearRecord`。

---

# 4. 星心值規則

成功完成一筆新的 ClearRecord：

**+5 星心值**

規則：

- 一筆 ClearRecord 最多獎勵一次
- 查看舊紀錄：+0
- 編輯：+0
- 再次儲存：+0
- 刪除：不扣回
- 關閉 App 後重開不得重複發放
- 同一筆資料不得因 reload / reopen 重複獎勵

ScoreAward 建議：

```ts
awardType: "clear_complete"
points: 5
sourceId: clearRecordId
```

由 persistence layer 防止 duplicate award。

---

# 5. 清醒星星規則

完成 ClearRecord 後，可選擇：

**存成清醒星星**

若使用者確認：

```ts
Star.type = "clear_mind"
```

規則：

- 建立清醒星星不另外加星心值
- 一筆 ClearRecord 最多對應一顆清醒星星
- 清醒星星代表這次覺察的紀念
- Clear 完成與「是否建立清醒星星」為兩個不同概念

核心：

> Clear 完成 = 行動獎勵
> 清醒星星 = 紀念這次覺察

---

# 6. 清醒紀錄：查看、修改、刪除

正式完成的 ClearRecord：

- 可查看
- 可重新打開六步流程
- 可修改
- 可儲存修改
- 可刪除

## 修改

修改後：

- 保留原 `createdAt`
- 更新 `updatedAt`
- 不再次給 +5
- 不重建第二顆清醒星星

## 刪除

刪除需二次確認：

> **刪除這次清醒紀錄？**
> 刪除後無法復原。

若此紀錄已有對應清醒星星，再詢問：

> **這次整理已經存成清醒星星，要一起刪除嗎？**

提供兩個選項：

1. **只刪紀錄**
2. **紀錄與星星一起刪除**

因此，使用者可以選擇刪除原始紀錄，但保留清醒星星作為回憶。

# 7. 資料模型草案

```ts
type ClearRecord = {
  id: string

  triggerType?: ClearTriggerType
  triggerText?: string

  facts?: string
  interpretation?: string
  unknown?: string

  emotions: ClearEmotion[]
  emotionIntensity: 1 | 2 | 3 | 4 | 5
  bodySensations?: BodySensation[]

  observations?: ClearObservation[]

  needs?: ClearNeed[]
  nextActionType?: ClearActionType
  nextActionText?: string

  clearMindStarId?: string

  localDate: string
  timezone: string
  createdAt: string
  updatedAt: string
}
```

## 資料模型原則

- Stable key 存入資料庫
- UI 顯示文字走 i18n
- 不將繁體中文顯示文字直接當作資料 enum
- 所有長度限制需在 data layer 驗證
- 不可只依賴 UI maxlength
- 不得自動截斷超長資料

---

# 8. V1 字數限制

| 欄位 | 上限 |
|---|---:|
| 發生什麼事 `triggerText` | 300 字 |
| 我確定知道的 `facts` | 300 字 |
| 我腦中正在想的 `interpretation` | 300 字 |
| 我現在還不知道的 `unknown` | 300 字 |
| 自訂下一步行動 `nextActionText` | 150 字 |

Clear 不定位為長篇日記。

若使用者需要較完整書寫，應使用「足跡／日記」功能。

---

# 9. V1 明確不做

本功能 V1 不做：

- AI 文字分析
- OpenAI API 或其他 AI API
- 自動分類事實／解讀
- 自動摘要生成
- 對方人格分析
- 紅旗判斷
- 關係健康分數
- 愛情百分比
- 心理疾病診斷
- 誰對誰錯的判斷
- AI 聊天機器人
- 自動替使用者決定下一步
- Native notification
- Photo Picker
- 照片儲存
- Cloud sync
